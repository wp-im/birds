Birds is moving from a visual prototype into a small, usable WordPress product.

0.5.3 · Semantic nested comment markup

  • Wrapped the native comment output in a semantic comment list and switched the WordPress walker to `ul` mode.
  • Child replies now render inside `.children`, so the existing depth indentation applies to the actual DOM tree.

0.5.2 · Threaded hierarchy output

  • Explicitly enabled WordPress threaded comment output so child replies render inside `.children` containers.
  • Preserved the native parent relationship and existing depth-aware reply links.

0.5.1 · Threaded reply repair

  • Fixed the native comment form template so the reply form is rendered by PHP instead of leaking its function call as page text.
  • Restored the WordPress comment_parent flow used by reply links and nested comment submission.

0.5.0 · A reusable Classic Theme boundary

  • Added native Classic Widgets support for a replaceable Context Rail instead of hard-coded site-specific sidebar content.
  • Added a compact Customizer surface for presentation choices: composer, rail, clock, footer metadata, feed size, and feed labels.
  • Unified feed pagination through the Theme query layer and added a native reusable search form.
  • Added a generic Account Page presentation contract with an optional Birds Core profile update flow.
  • Moved fallback Open Graph and Twitter metadata ownership into Birds Core while keeping the Mac OS preview renderer in the Theme.
  • Added reusable confirmation behavior for destructive front-end operations and removed site-specific login/account assumptions.

Birds Core 0.2.0 · Generic companion operations

  • Added capability-aware profile updates with optional local avatar uploads using native WordPress media APIs.
  • Added filterable login and account URL contracts so site integrations can replace routes without changing the public package.
  • Added SEO-plugin detection to avoid duplicate fallback metadata.
  • Kept all content, comments, permissions, nonces, and persistence inside WordPress Core with no custom tables.

0.3.0 · Theme completeness

  • Added a compact front-page product introduction when a static WordPress front page is configured.
  • Restored visible spacing between the composer identity row and the writing area.
  • Kept the Birds navigation visible below the WordPress Admin Bar during anchored scrolling.
  • Unified the left and right titlebar controls into a simpler pair of matching boxes.
  • Added a real site footer with short-page bottom placement.
  • Improved Page and Thread semantics with headings, multipage support, post titles, and adjacent-post navigation.

0.2.0 · Theme refresh

  • Sharper feed-first home experience for immediate publishing, reading, and replies.
  • Shared post presentation across home, search, author, category, archive, and thread views.
  • Mac OS 9-inspired shell refined into a responsive, readable interface.
  • Theme hooks prepared for focused front-end post and reply controls.

Birds Core 0.1.0 · Interaction layer

  • Front-end publishing for logged-in users with the appropriate WordPress capability.
  • Practical post controls: edit, move to trash, and open or close replies.
  • Practical reply controls with capability and time-window checks.
  • Native WordPress admin-post, nonce, post, comment, and trash flows.

0.1.0 · First release

  • First standalone Birds Classic Theme release.
  • Mac OS 9-inspired shell with a P2-shaped live feed.
  • Native WordPress comments rendered as thread replies.
  • Responsive desktop and mobile layout with no required front-end framework.

Still deliberately small

Birds does not add a custom database, proprietary content model, follows, notifications, presence, or activity ranking. The next release should be driven by actual use of the feed, not by a checklist of social features.
